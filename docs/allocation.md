# Как сообщество выбирает работу

У основателя обычная учетная запись участника с той же формулой веса. Если голосует один человек, его подходящий кандидат идет первым. Правила голосования и команды описаны в [инструкции](community.md). Для аудита доступны [голоса, выбор и квитанции](../campaigns/ledger.json) и [замороженные списки задач](../campaigns/archive). Права администрирования GitHub и исполнение Actions остаются в исходном репозитории. Любой участник может скопировать открытый журнал и пересчитать порядок по коду.

С кампании 2026-W49 команда начинает с лучшего подходящего кандидата по голосам. Остальные места распределяются по дефициту оценочных минут за четыре предыдущие недели и текущие уже выбранные пакеты. Для каждого задания берется середина его оценочного диапазона, для неизвестной оценки используется 30 минут планирования. После досрочного завершения система сначала проверяет следующего подходящего кандидата по голосам. Когда список исчерпан, работает поиск. Версия этих правил, кандидатские оценки и причины выбора сохраняются в снимке для `campaign/verify-week`.

| Направление | Целевая доля работы | Что ищет система |
|---|---:|---|
| Общественная польза | 40% | Доступность, протезирование, цифровое здоровье, медицинские изображения, онкология и DICOM |
| Развлечения | 20% | Игры, музыка, творческое программирование |
| Защитная безопасность | 15% | Документация по приватности, управлению секретами и аутентификации |
| Фундаментальная наука | 15% | Математика, проверка доказательств, астрономия и научные вычисления |
| Другие проекты | 10% | Подходящие задачи остальных направлений |

Единица учета — один выбранный репозиторий с пакетом конкретных задач. Проценты описывают места, фактическая длительность работы участников может различаться. Поиск использует темы GitHub и общий поток открытых issues. В каждом направлении поисковая тема меняется еженедельно. После проверки лицензии, задач и емкости ревью первое место недели получает лидер голосования среди подходящих кандидатов. Для следующих мест система выбирает доступное направление с наибольшим накопленным отставанием от цели. При одинаковом дефиците выше кандидат с лучшим результатом голосования, затем учитываются оценка задач и имя репозитория. В резервном раунде снова первым идет следующий кандидат из голосования. Дефицит переносится между неделями. Голоса и доступность задач могут изменить фактические доли. Темы задают сами проекты, поэтому классификация приблизительна.

Стартовый размер — три проекта. Если к границе недели приняты PR по всем исходным задачам всех выбранных пакетов, следующая неделя получает одно дополнительное место, максимум восемь. При завершении менее половины пакетов размер снижается на одно место, минимум одно. В остальных случаях размер сохраняется. В течение недели после завершения всех пакетов очередная сверка добавляет один следующий подходящий проект из рейтинга. После исчерпания рейтинга действует автоматический поиск. Пустая выдача повторно проверяется на очередной сверке. Закрытая посторонним человеком задача без зарегистрированного merge сама по себе не дает зачета. Архив сохраняет исходный состав пакета.

**English.** Every member uses the same ballot. Eligible votes lead. Automatic seats compensate for underrepresented tracks. Previous completions resize the next week. Completing the full slate opens one reserve seat per reconciliation.

**Español.** Todos votan con las mismas reglas. Los proyectos elegibles con votos tienen prioridad. Las plazas restantes compensan las categorias con menor representacion. Completar la semana abre una plaza de reserva.

## Добровольные вычисления

Встроенная задача проверяет конечный диапазон гипотезы Гольдбаха. Для каждого четного числа от 4 до заданной границы участник находит пару простых слагаемых. Один человек публикует в обсуждении задачи версию коммита, верхнюю границу и число частей. Участники договариваются об индексах, запускают работу на своих компьютерах и передают файлы любому проверяющему. Все работают на одной версии программы. Координатор, общий аккаунт, сервер с входящими портами и доступ к чужому компьютеру для расчета не требуются.

[Создать публичную вычислительную задачу и пригласить участников](https://github.com/TONstories/repo-neighbor/issues/new?title=Community+compute%3A+Goldbach&body=Commit%3A%20%0ALimit%3A%2010000%0AParts%3A%202%0AClaim%20a%20zero-based%20index%20in%20a%20comment%20before%20starting.%20Attach%20the%20result%20to%20this%20issue.)

Например, для двух компьютеров первый и второй участники соответственно выполняют:

```sh
python3 compute/goldbach.py work 10000 2 0 > part-0.json
python3 compute/goldbach.py work 10000 2 1 > part-1.json
```

Получатель обоих файлов независимо проверяет каждое свидетельство и полноту диапазона:

```sh
python3 compute/goldbach.py verify 10000 2 part-0.json part-1.json
```

Ожидаемый результат — 4999 проверенных чисел. Потерянную часть можно выдать другому участнику. Задания ограничены миллионом и 1024 частями. Это конечный вычислительный эксперимент. Общее доказательство гипотезы остается отдельной научной задачей. Перенос файлов и распределение индексов выполняют участники.

## Какие практики использованы

- Debian закрепляет коллективные решения разработчиков в конституции. В Repo Neighbor порядок выбора и правила пересчета открыты, у владельца отсутствует отдельная команда назначения проекта. [Конституция Debian](https://www.debian.org/devel/constitution)
- BOINC объединяет добровольно предоставленные вычислительные ресурсы. Здесь использованы независимые порции работы и проверка результата у получателя. [BOINC](https://github.com/BOINC/boinc)
- Научный отбор опирается на открытые задачи и проверяемые результаты. Нобелевские категории включают, например, физику и физиологию или медицину. Отдельной премии по математике среди них нет. [Категории премий](https://www.nobelprize.org/prizes/)
